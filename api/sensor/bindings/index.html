striqt.sensor.bindings¶

Sensor bindings, which pair a sweep spec type with the source, sink, and peripheral implementations that run it.

the built-in sensor bindings.

Each binding pairs a source backend with the spec types that configure the backend. The sensor_binding key of a sweep file selects a binding by name.

read_iq ¶

read_iq(
    overlaps: tuple[int, int] = (0, 0),
    *,
    burst_index: int = 0,
    resume: bool = False,
) -> tuple[Array, int | None]

read the IQ of one burst segment of the armed capture.

The read of segment 0, or of a segment with resume, triggers the backend and applies the transient holdoff. The read of a later segment continues the enabled stream from the samples carried over after the previous segment. The carryover is kept for the next segment and cleared after the last segment of the burst.

Parameters:

  • overlaps (tuple[int, int], default: (0, 0) ) –

    the (lead, tail) overlap in source samples around the record

  • burst_index (int, default: 0 ) –

    the index of the segment within the burst of the armed capture, from 0 to capture.burst - 1

  • resume (bool, default: False ) –

    if True, segment burst_index is read as the first segment after a stream error, with no carryover

Returns:

  • Array –

    (samples, start_time_ns): the samples as a C-contiguous complex64

  • int | None –

    array with shape (ports, count) in the namespace of the source

  • tuple[Array, int | None] –

    array_backend, and the time (in ns) of the first record sample, or

  • tuple[Array, int | None] –

    None when the record is filled from the carryover without a backend read

Raises:

  • ValueError –

    if overlaps is not 2 non-negative integers

  • OverflowError –

    on a stream overflow after the first read of a segment, or on any read of a segment that continues the stream

  • MemoryError –

    if the backend reports more samples than requested

acquire_burst ¶

acquire_burst(
    overlaps: tuple[int, int] | None = None,
    *,
    queue: AcquisitionQueue | None = None,
    finalize: Callable[[AcquiredIQ], AcquiredIQ]
    | None = None,
) -> list[AcquiredIQ]

acquire the capture.burst segments of the armed capture.

The segments are read back to back with the stream enabled. After a stream error or overflow during segment k, the backend runs prepare_retrigger and the read is repeated, up to source_info.retries times per burst. Under bursts.on_gap='skip', segment k is read again as a first segment. Under 'except', the segments of the burst still in queue are removed and the burst restarts from segment 0.

Each segment passes through finalize before it is queued or returned. When queue is full, the put of a segment of a capture with burst above 1 is skipped with a WARNING on the source logger under 'skip' and raises under 'except'. The put of a capture with burst 1 waits for a free slot.

Parameters:

  • overlaps (tuple[int, int] | None, default: None ) –

    the (lead, tail) overlap in source samples, or None to derive the overlap from the capture and the analysis target

  • queue (AcquisitionQueue | None, default: None ) –

    the queue that receives each segment, or None to return the segments

  • finalize (Callable[[AcquiredIQ], AcquiredIQ] | None, default: None ) –

    a function applied to each segment before the queue put

Returns:

  • list[AcquiredIQ] –

    the segments in order when queue is None, otherwise an empty list

Raises:

  • ValueError –

    if burst is above 1 and capture.duration is not a whole number of trigger_strobe periods

  • AcquisitionOverrunError –

    if queue is full under bursts.on_gap='except'

  • ReceiveStreamError –

    on a stream error once the retries are exhausted

  • OverflowError –

    on a stream overflow once the retries are exhausted

  • ThreadInterruptRequest –

    in a worker thread, when cancel_threads has been called

bind_sensor ¶

bind_sensor(
    key: str,
    sensor: Sensor[TS2, TP2, TC2],
    schema: Schema[SS, SP, SC, SA, PS, PC],
    register: bool = True,
    *,
    module: Optional[str] = None,
) -> type[Controller[SS, SP, SC, SA, PS, PC]]

bind the implementation classes of a sensor to spec types under key.

The returned Controller subclass has the class attributes sensor (a SensorBinding) and schema. Its sensor.sweep_spec_cls is a subclass of the action spec type, tagged with key in the sensor_binding field. In that subclass, source, peripherals, captures (when the action declares the field), and analysis (when the action is a Sweep) are annotated with the types in schema. A sweep file with sensor_binding equal to key decodes to an instance of that subclass. The tagged subclass has the class attributes sensor, schema, controller (the returned class), and sweep_cls (the bound Sweep class with the same spec types, or the tagged subclass when the action is a Sweep). The tagged subclass of an unregistered binding is decoded only by explicit type.

Parameters:

  • key (str) –

    the sensor_binding value of sweep files, and the registry key

  • sensor (Sensor[TS2, TP2, TC2]) –

    the implementation classes; the sensor of a registered controller selects the same hardware for the action in schema

  • schema (Schema[SS, SP, SC, SA, PS, PC]) –

    the spec types; schema.action selects the action spec type and schema.analysis the analysis group

  • register (bool, default: True ) –

    if True, the binding is registered under key for get_controller, and the tagged subclass is added to the union that get_tagged_sweep_type returns

  • module (Optional[str], default: None ) –

    the __module__ of the returned class; the module of the caller when None

Raises:

  • TypeError –

    if sensor or schema has the wrong type, if key is already registered, if sensor.sweep_spec_cls and schema.action name different non-default types, if the check_schema of the action type rejects schema, or if a field of schema.analysis is not a registered measurement
