striqt.sensor.specs¶

schema for the specification of calibration and sweeps

Sweeps and captures¶

Spec structs for sweeps, actions, capture settings, and the loops that expand one capture into several.

ActionSpec ¶

Bases: SpecBase, Generic[SS, SP, SA]

the top-level spec that an action runs.

An instance is decoded from a file against the tagged class of a sensor binding or constructed in code. The source, peripherals, and sink blocks name the resources that every action opens. source and peripherals are the spec types of the binding named by the sensor_binding tag.

check_schema(schema: Any) -> None

raise if the spec types of schema cannot configure this action.

The base implementation accepts every schema.

Parameters:

  • schema (Any) –

    the Schema of the binding

Raises:

  • TypeError –

    if a spec type of schema lacks a field the action requires

BurstOptions ¶

Bases: SpecBase

the bursts block of a Source: the policy for the segments of a capture burst.

A capture with burst above 1 is acquired as that many back-to-back segments with the stream left enabled, and the segments are sample-contiguous. The hardware clock syncs once per burst. Acquisition of a capture with burst 1 blocks until a buffer slot is free and is never dropped.

on_gap class-attribute instance-attribute ¶

on_gap: one of ['skip', 'except'] = 'skip'

the response to a timing gap in a burst: 'skip' drops a segment when the queue is full and resumes after a stream overflow; 'except' raises on a full queue and restarts the burst after a stream overflow

buffers class-attribute instance-attribute ¶

buffers: int = 1

maximum number of acquisitions queued ahead of analysis (Constraints: >= 1)

trigger_on class-attribute instance-attribute ¶

trigger_on: one of ['first', 'all'] = 'first'

'first' runs the signal trigger on the first delivered segment of a burst and applies that lag to the rest; 'all' runs the trigger on every segment

CapturePlan ¶

Bases: ActionSpec[SS, SP, SA], Generic[SS, SP, SC, SA]

an ActionSpec with the captures, loops, and adjust_captures blocks.

The loops are expanded over captures into the sequence of captures that the action runs, and the adjust_captures remaps for the open source are applied to each expanded capture. Construction rejects a repeat loop that is not the outermost entry, two loops over one field, and a loop over a field that the listed captures set to different values.

adjust_captures class-attribute instance-attribute ¶

adjust_captures: dict[str | one of ['defaults'], dict[str, CaptureRemap | float | int | str | bool | None]] = msgspec.field(default_factory=dict)

Remaps of capture fields by source id (or 'defaults'), keyed by the value of another capture field; lookup keys are converted to the type of the keyed field

CaptureRemap ¶

Bases: SpecBase

an entry of the adjust_captures block: a capture field set by lookup from the value of other capture fields.

The key names one or more fields of the capture after the loop point is applied, and the lookup maps each key value (a tuple, or its JSON array string in YAML, for several key fields) to the value of the adjusted field. A key value absent from the lookup takes the default when one is set; otherwise the field is left unset for an optional remap, and the spec is rejected for a required one.

CellChannel ¶

Bases: SpecBase

one 5G NR channel of the cell_channels table of a Cellular5GNRSweep.

A capture with the center_frequency of the channel is acquired at the sample rate that striqt.waveform.comms_5gnr.nr_sample_rate derives from channel_bandwidth and subcarrier_spacing, at or above min_sample_rate, with analysis_bandwidth equal to channel_bandwidth. The cellular measurement parameters are set from the remaining fields through the adjust_analysis of the capture, with ssb_case None selecting the TS 38.213 §4.1 case for the spacing ('c' at 30 kHz). Only a subcarrier_spacing of 30 kHz is accepted, and tdd_frame_slots is 1 character per slot of the 10 ms frame or 1 character for every slot.

RF center frequency (Constraints: > 0, units: Hz)

nominal 5G NR channel bandwidth (3GPP TS 38.104 §5.3) (Constraints: > 0, units: Hz)

Subcarrier spacing (15e3, 30e3, 60e3, etc) (Constraints: units: Hz)

index locations in the SSB, or a cell search case from 3GPP TS 38.213 Sec. 4.1)

guard bandwidths excluded at the (low, high) edges of the channel (Constraints: units: Hz)

string composed of ('d', 'u', 's') specifying the sequence of slots in 1 TDD cellular frame, or None to fill with downlink

Cellular5GNRAnalysis ¶

Bases: SpecBase

the per-measurement settings of a Cellular5GNRSweep.

Each field is named for a measurement, and None disables the measurement. A block enables the measurement and holds only the parameters that the channel does not fix. The remaining parameters are set from the cell_channels entry at the center frequency of the capture and from the subcarrier spacing, or stay at the measurement default.

Cellular5GNRSweep ¶

Bases: CapturePlan[SS, SP, SC, SA]

the spec of a sweep over 5G NR channels.

Each entry of captures names a channel by center_frequency, and cell_channels maps a label to the CellChannel at that frequency. The sample_rate and analysis_bandwidth of a capture are left at the class defaults and set from the matched channel. A loop over center_frequency is rejected, two cell_channels entries must not share a center_frequency, and every channel in use must share one subcarrier spacing.

check_schema classmethod ¶

check_schema(schema: Any) -> None

raise unless schema can configure a sweep over cell channels.

The capture type must have a center_frequency field, and schema.analysis must declare every field of Cellular5GNRAnalysis with the spec type of the BuiltinAnalyses field of that name.

Raises:

  • TypeError –

    if the capture type lacks center_frequency, or if schema.analysis lacks a field or declares a different spec type

FrequencyBinRange ¶

Bases: LoopBase

a loop over a field on a grid of equal steps symmetric about 0.

The points are spaced by step on a grid centered on 0 that spans ceil((stop - start) / step) steps, and a point outside start to stop at either end of the grid is dropped. Each point is a multiple of the step or of half the step.

A loop names a field of either the capture or the analysis, and get_points returns the values that the field takes, one expanded capture per point. Loops are nested in declaration order, outermost first.

ManualYFactorCalibration ¶

Bases: CapturePlan[SS, SP, SC, SA]

the spec of a Y-factor calibration with a hand-switched noise diode.

An analysis block is accepted, discarded, and reported with a DeprecationWarning. More than one capture is accepted only when calibration.implied_loops names the fields in which the captures differ. source.calibration must be None, and every capture must have burst equal to 1. A bound spec is rejected when the runner cannot derive the calibration sweep.

Sweep ¶

Bases: CapturePlan[SS, SP, SC, SA]

the spec of a sweep.

analysis is an instance of the group that Schema.analysis names for the binding, and is evaluated on each expanded capture with the adjust_analysis of the capture applied on top. options selects the warmup, IQ reuse, and the loop_only_nyquist filter of the expansion. Construction validates each unique capture against the registered measurements and the conditioning signal path.

SweepOptions ¶

Bases: SpecBase

the options block of a Sweep: IQ reuse, the Nyquist filter of the expansion, and the GPU warmup.

With IQ reuse, the IQ of the previous acquisition serves a capture with the same radio settings, and the Nyquist filter drops each expanded capture with a finite analysis bandwidth above the sample rate of the capture. The warmup runs the sweep once over empty buffers before the first acquisition when a GPU backend is in use.

skip_warmup: bool = True
